# 审锁纪要 · 插笼抬冻口径封存

- 封存日：2026-11-23
- 范围：入笼服务（cages_svc）、账户服务（bonds_svc）、对账服务（reconcile_svc）、锁服务（locks）
- 事故底案：入笼提示成功、名册见新笼，但当事人冻结余额未抬，互证栏假绿，柜员按旧冻额超额再押。

## 口径（二选一，已封存）

**选定甲路径：插笼与抬冻同一事务，同生同灭。**

- 新笼名册写入成功 ⇒ 账户 `frozen` 必在同一事务内抬高 `amount`；任一侧失败，整笔回滚，正式零改。
- 乙路径（冻结未抬则抹回新笼可见行）**不采用**；插笼抬冻只走甲一种落库侧，两边不得混用。
- 禁止第三套中间写法（影子笼、事后补抬、异步对平、仅调列表刷新频率等一律禁止）。

## 拒写规则

- 业务校验拒写（户不存在 / 状态异常 / 可用不足 / 笼编码撞车）：整笔回滚，笼零增、冻结零改，只留 `cage_freeze_reject` 拒写审计痕（独立连接提交，不随业务事务回滚）。
- 偏离本纪要即记「插笼抬冻偏航」，并拒一切正式写入。

## 并发争用规则（与命运说明分段，不揉同一句验收）

- 两名经办对同一当事人账户同时入笼，须抢账户锁 `bond:{party_key}`。
- 后到会话只记争用：`contention_log` 留痕（独立提交，业务回滚不带走），返回 409，不死磕成功态，业务零写。
- 锁获取撞主键（真并发同插）视同争用，同样只记争用。

## 互证口径

- 当事人级：`account.frozen == Σ(活笼 available)`，活笼状态 ∈ {已冻结， 核验通过， 核验违约， 部分解笼， 部分罚没}。
- 互证栏绿必须来自实算比较，禁止硬编码真值（假绿即事故）。
